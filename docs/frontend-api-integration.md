# Studio TV frontend API integration

Iteration 03, 2026-10-05. The implemented mappings below connect the native frontend to STUDIO's Go/DDD modules and PostgreSQL state. The immutable native UI, canvas animation, pet, minimap, local WebGL director controls and OpenCut editor remain the rendering/editing implementation. Billing, community and public publishing are disabled in this internal edition.

**IMPLEMENTED** describes an actual product route and frontend mapping, with explicit failures and ownership/version checks. **RESERVED** describes a product protocol that still returns501. This inventory is not a claim that every original-site button or advanced workflow has been implemented or accepted in a browser. Model requests use the independent Models Router with its own PostgreSQL and an explicitly configured TEST MODE adapter; task and file persistence remain actual STUDIO/Router operations. Acceptance evidence and deployment status are at the end.

## Data source, authentication and lifecycle

`service/runtime.ts` creates one `ProductClient`, `AuthSession` and `ServiceStorage`. The client extends the existing v1 API client and reuses its memory token and captured raw transport for `/api/v2`. V2 targets are bounded relative STUDIO paths; caller authorization/Router identity headers cannot override the current STUDIO identity. The raw transport bypasses the native request adapter. Other-origin native fetches strip STUDIO/native authorization headers and omit credentials. Router credentials and vendor models are server concerns.

IPAC supplies the actual identity; protected requests verify the live session and `tv.access`, then enforce owner access to private STUDIO resources. IPAC workspace, role and permission management do not become product UI concepts. STUDIO's shared IPAC HTTP transport bounds outbound concurrency to two because the deployed IPAC performs Argon2 verification on every Basic-authenticated request. Each admitted request still performs its own live session/permission check; there is no cached authorization, automatic retry or bypass.

In service mode the bootstrap imports no preview canvas/asset runtime and reads neither `fixtures.json` nor `media-map.json`. Its compatibility global exposes actual server-loaded project memory. Preview fixtures, fake preview identity, preview sockets and preview EventSource only run in preview mode. Declared unsupported operations return501, unknown paths return404, and backend errors remain failures. Existing real project/snapshot APIs, optimistic versions, upload sessions and account/IPAC checks are reused.

Logout/revocation abort requests, task waits, assistant streams/sockets, history scans, organization reads, Studio polls/byte streams and resource reads. V1 refresh/revocation checks request scope first, so a late old-account401 cannot revoke a replacement identity. Autosave completions also check the current canvas attachment epoch. Epoch checks reject late completions even when a transport ignores abort. Cached models, resource versions, signed URLs, catalog pointers, Blob skill files and captured assistant state are cleared. Explicit logout still waits for the actual final snapshot and preserves unresolved conflicts. Native signed Studio preview/media/anchor sources are blanked on clear; pending output tabs close. Static generation/navigation UI hooks remain installed with current-auth guards across logout/login.

## Generation and model test mode

The own `native-integration.ts` imports the observed native manager exports `bt` and `le`; it updates generation/cancel hooks. Narrow node/retry button and keyboard adapters use the parameter panel's parent callback, preserving parameter flushing while skipping the separate SKU/wallet wrapper. Normal groups call STUDIO execution; their original confirmation requires the original price/wallet. Specialized storyboard/video/entity group buttons retain native planning/picker controls. The launch composer is source-confirmed to gate on real inputs/model/upload state, with price only displayed. Storyboard board creation stays local; ordinary storyboard creation can continue into a real STUDIO task. No fake wallet, free quote, SKU, original API key or generated output is supplied.

Actual `/model-capabilities` records provide refs, versions, kind, availability and parameter schema. The adapter maps schema controls to observed native `list`, `int`, `float`, `boolean`, `text` and media parameter types. Unselected legacy/default model choices and isolated tools select only advertised, available `testMode:true` capabilities. Explicit selected refs remain actual catalog refs. Names use `[TEST MODE]`; completed native nodes use a visible title/badge and text results/history use the same marker. Structured output retains its real schema/data and a testMode flag. Assets always resolve through owner READY metadata.

The native subtype mapping covers all 20 requirement kinds: LLM, TEXT_TO_IMAGE, IMAGE_TO_IMAGE, IMAGE_EDIT, IMAGE_ENHANCE, IMAGE_VARIATION, IMAGE_CUTOUT, IMAGE_LAYER_DECOMPOSITION, TEXT_TO_VIDEO, IMAGE_TO_VIDEO, OMNI_REFERENCE, VIDEO_TO_VIDEO, VIDEO_ENHANCE, VIDEO_DEPTH, TEXT_TO_AUDIO, TEXT_TO_MUSIC, AUDIO_TO_AUDIO, AUDIO_SEPARATION, GENERATE_3D_MODEL and GENERATE_3D_WORLD. Availability comes from the actual Router catalog rather than invented local models.

Before execution, catalog media is materialized and current owner READY assets are checked. Graph media is canonical `rhtv-asset:<id>`; task create uses a fresh UUID Idempotency-Key. Only selected generation targets, including nested group descendants, are given a capability; existing source/upload nodes remain sources. Persisted task plans update the existing manager states/output and `historyStorage.source=remote`. Declared ASSET and current domain ARTIFACT output aliases both resolve real STUDIO assets. Persisted running nodes resume status reads rather than creating new runs. Concurrent submissions of one target coalesce; current node/task ownership and accepted task revision reject superseded results. Output resolution and generation failure patches cannot write into a replacement canvas manager.

Verified result patches use the immutable manager's bounded `allowFields: ['output', 'status']` and its actual in-flight `processing` state. Once a current terminal plan has been applied and the queue flushed, an authenticated current-manager/current-project/current-task callback calls `c5.getState().unmarkLocalRunning(nodeId)`. Pending states, obsolete tasks, old revisions, disposed integrations and late logout responses cannot release a current node's running overlay.

Entity generation captures the exact native script render scope, its j0 editing context and ROr character-view Promise. It replaces that script's generation runner and exact onGenerate/batch/global/group callbacks before the original API-key preflight. Native cancellation, layout, real selection, unsaved parameters/count, character view, entity metadata, style and explicit user references are retained. Only selected real nodes become rh-image execution snapshots; previous outputs/history are excluded from model inputs. Unrelated callbacks and React hook order are preserved.

rh-ai execution reads the current APP revision and complete content.inputNodes form, restores native numeric/boolean serialization, validates current options/bounds and resolves media to owned READY rhtv-asset references. POST /app-runs uses an advertised available TEST MODE capability selected by the app output type. APP-containing groups/graphs execute in dependency order using separate actual task IDs and actual completed upstream outputs. This is a client orchestration of persisted tasks, not an atomic aggregate; source/identity changes stop later submissions. Missing vendor workflows are unnecessary for this explicit model test invocation.

## Trusted catalog media seam

The resource adapter registers URLs only while reading actual persisted SYSTEM catalog DTOs. Each pointer is `{family,resourceId,revision,path}` with RFC6901 path inside resource content. Current families use CHARACTER, WORKFLOW, PROMPT, SKILL, APP, VOICE or catalog namespace names. Before saving/using such media, storage POSTs `/catalog/media/materialize` with a UUID and that pointer, **without a vendor URL**. The expected result is `{asset:<actual owner READY asset>}`.

Backend must re-read the exact permitted catalog/version/path and import/copy approved bytes through STUDIO asset storage. Missing permissions/version/import failures propagate. Current core/product_assets.go implements this route against exact persisted SYSTEM records and registered approved local catalog files, importing owner READY assets. Missing captured URLs or unregistered media remain real failures; no browser external URL is accepted.
