# 2D 画板生成与风格修复（2026-10-08）

## 实际问题

- 原生 `sketchboard_style_live/manual` 字典在 STUDIO 目录内为空，“显示更多”只有空菜单。
- 原生画板在第一张成图存在之前，将运行中状态覆盖成“等待绘制”。生成任务实际已提交，但用户看不到进度。
- 画板进入 `/project/canvas/:id/sketchboard` 后释放画布 manager，状态必须按子路由的项目 ID 隔离。
- 原生“平均生成时间 4–6s”和最多 130 次每秒轮询属于原站假设，不符合当前异步 Codex Image 编辑模型。

## 修复范围

- `apps/web/src/service/sketchboard.ts` 定义 STUDIO 自有的六种风格：二次元动漫、线稿插画、水彩绘画、水墨国风、3D 质感、产品设计；live/manual 共用同一集合。它们是提示词预设，不是六个独立模型或原站私有工作流。
- `ResourceAdapter` 仅投影这两个明确的 STUDIO 字典，其他字典继续请求服务端。原生更多菜单、选择行为保留。
- `ExecutionAdapter` 将风格 `styleCode + stylePrompt`、生成模式及 `SKETCH` 引用提交给真实 `IMAGE_TO_IMAGE` 能力；无选填描述时提供草图保形指令。未知风格拒绝，不静默替换。
- 独立状态显示上传/提交、生成中；旧任务响应不覆盖较新的提交状态；退出画板或登出清除当前视图状态。
- 草图状态查询每轮最多等待 6 秒，约 15 分钟的原生轮询窗口；会话改变中止等待。仅修改草图状态路径，不改变其他图片工具。取消状态转为明确失败，避免原生轮询继续等待。
- 删除不可靠的 4–6 秒展示，改为“可能需要数分钟”。预检错误接现有 generation-diagnostics / log_id / 飞书告警链。
- 没有改动冻结原生资源、模型路由服务或后端运行服务。

## 能力边界

当前是草图变化后自动提交异步图片编辑，不是逐帧或秒级模型。持续作画期间的最新草图补跑、暂停后的上游任务取消语义仍需独立改造；本次不把这些标为已完成。暂停停止原生自动更新，已提交任务仍可能在后台完成。风格样例只验收代表链路，不承诺全部风格的美术质量已逐项验收。
