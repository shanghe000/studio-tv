# 画布恢复与自动保存检查

2026-11-05。对 RunningHub 的公开代码与已保留的网络实验继续核实后，修复 Studio TV 中可以独立复现的恢复问题。本次没有把 Studio TV 的服务端操作协议改成 Yjs 协议，也没有改动模型参数或收费生成入口。

## 参考方案的证据与边界

RunningHub 的图结构使用 Yjs，持久待发队列先写 IndexedDB，再发送，持久确认后定向删除，队列中的拓扑操作保留顺序。其 provider 每 3 秒检查最后入站消息，超过 30 秒才关闭失效连接；页面可见/焦点唤醒对非 idle 状态直接返回。这些是公开发布代码与原始函数受控执行的直接证据。之前真正命中 BFCache 的约 32 秒恢复与该机制吻合，但缺少当次调用栈，不能认定为唯一因果。普通离线样本的约 33 秒是最终读回时间，不能视为精确恢复时延。

采用的是明确有助于体验的恢复、持久保护和确认规则。Studio TV 仍由服务端验证并持久化节点与连线操作，前端保留已确认内容和未确认队列。内部一致性字段不要求用户操作版本、合并或导出草稿。

## 确定问题与改动

- 页面恢复依赖有限的事件组合。补齐 BFCache 返回、冻结恢复和联网恢复，清除临时传输退避；有效入站活动用于判断连接健康，避免健康标签每次切回都断流。长时间没有入站的连接在回到前台时立即重新追赶。
- 旧 SSE 路径可能永远等待已失效响应。头部/快照/事件读取设定 15 秒无进展上限，有数据持续到达的大画布不会因总下载时长超过 15 秒被中断，SSE 无入站字节 25 秒后重新读取，正常 10 秒心跳续期。保持最后实际应用的游标，未完整的帧不能推进确认。
- 原 JSON 解码在响应头到达后丢失取消关联。响应体读取持续绑定请求和账号，离开画布、截止时间或退出账号可取消，迟到的权限错误不能影响新账号。完整画布不受小事件帧大小限制。
- 写入短暂失败在少量尝试后停止。现代画布现在按 1、2、5、10、15 秒退避，随后保持最多 15 秒间隔；离线期间不自动发送，联网后继续。重试仍使用原批次身份和内容，未知结果不能改写或跳过。代理 HTML 或截断 JSON 被归为可恢复的传输错误，明确的服务端权限/输入拒绝仍保留。持续实际写失败超过 30 秒且本机持久保护有效时，只提示一次等待自动保存，恢复后清除通知状态。
- BFCache 后页面 owner 变化，迟到确认可能删错待发记录的地址。保存逻辑批次到物理存储键的映射，确认只清理原条目。
- 系统时钟回拨可能打乱恢复顺序。新条目的时间不早于当前待发条目，持久化 order 继续提供同时间顺序，即便底层枚举反转也不改变编辑次序。
- 临时存储错误曾在全部修改确认后永久残留。最后一项获得服务器确认后重查队列，已解除的错误恢复；坏记录和仍未确认的数据保留。

## 验证范围

真实浏览器运行正式网页构建，调用本机真实 Go 路由与独立 PostgreSQL 测试库。只有身份、素材目录与故障注入来自测试设施；没有修改用户项目，也没有执行模型生成。拖动均通过页面鼠标操作，收敛同时读取节点 DOM。

| 场景 | 实际观测 |
|---|---|
| 模拟代理持续保持 SSE 连接但吞掉所有字节，普通 HTTP 可用 | 原构建超过 51 秒仍显示旧坐标，新构建约 25.8 秒自动补齐。该数据是受控静默连接故障，不是正常同步时延。 |
| HTTP 保存连续返回四次 503，读取和权限始终正常 | 第五次在首发约 18 秒后自动保存；五次提交内容完全一致，待发队列清空，无人工处理卡片。 |
| 页面在 BFCache 中，另一页移动节点，再按后退 | pageshow.persisted=true，文档 nonce 与 timeOrigin 未变，约 120 毫秒看到最新位置并可编辑，没有恢复提示。 |
| 完全离线再恢复联网 | 现有页面在完全离线时保护为只读，拖动没有产生编辑；复网约 105 毫秒恢复可编辑，无需按钮。这不证明或承诺支持离线新增编辑。 |
| 冻结页面期间另一页移动，解除冻结 | 约 14 毫秒观察到相同 DOM 坐标，没有恢复提示。该数字包含浏览器可能已有的缓存入站消息。 |

另以实际 ReadableStream 和可控时钟验证响应头后卡住的 JSON、晚到权限拒绝、健康心跳、连续恢复事件、离开页面的取消，以及队列确认、时钟回拨和存储恢复。明确拒绝的保存不会被普通权限轮询反复提交。它们不是人工线上故障的复现声明。

真实长时间离线仍意味着其他设备只能看到服务器已确认的内容；此处不能承诺离线设备之间实时一致。本机保护也不能抵抗用户主动清除浏览器数据或存储不可用。
