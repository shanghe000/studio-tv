# RunningHub 无限画布功能设计参考

研究日期：2026-10-06。完成7轮原站Agent访谈、51个功能段阅读检查点；当前添加菜单10家族均覆盖。用途：STUDIO 的供应商无关功能契约与实现排序。研究对象为 `rhtv.runninghub.ai` 无限画布，不是 RunningHub 全站的 ComfyUI 节点全集。

## 结论与范围

无限画布的主要价值是把创意、可复用角色/场景素材、分镜、生成结果、音频时钟和最终剪辑放进同一持久项目，允许人手动调整与 Agent 分阶段编排。[官方文档][原站Agent自述] 普通媒体节点只是底座；脚本策划、3D/导演台、画板、视频编辑器与 AI 应用是独立工作面，不能归为一张“模型菜单”。

本次只阅读公开文档、已登录页面及页面实际加载的公开前端，向原站 Agent 发送产品咨询。没有真实媒体生成，没有执行工作流，没有新增或修改画布节点。Agent 的回答只代表其可见工具契约：例如它不知道音乐生成、文本节点 LLM 和姿态控制，但公开文档/前端都有相应能力，所以不能把“不知道”当作产品不存在。

证据标签：**[官方文档]** 产品方说明，可能有营销夸张/版本滞后；**[实际UI或源码声明]** 当前菜单/客户端规则，证明入口与组包路径，不等同后端运行成功；**[原站Agent自述]** 本次咨询回答，未经真实任务验证；**[推测/未确认]** 推导或缺口。关键矛盾见后文。目录覆盖、原问题与回答摘要分别见 [覆盖记录](runninghub-docs-coverage-2026-10-06.md) 和 [访谈记录](runninghub-agent-interview-2026-10-06.md)。细粒度历史按钮与参数目录复用 [2026-10-05 功能矩阵](model-function-matrix.json)（214 表行、294 细粒度功能、162 人像预设、42 个目录模型；这些是该次采集计数，不是本次产品全部能力数）。

## 1. 节点、功能与模型必须分三层

当前实际“添加节点”菜单有 **10 个入口**：文本、图片、视频、音频、3D、导演台、脚本策划、分镜格子、视频编辑器、AI 应用。[实际UI或源码声明 U] 分组/注释是结构元素；上传/从作品导入是素材来源，画板是工作面入口，不应凑成生成节点种类。

当前源码还声明 **17类内部节点类型**，覆盖复刻分析/请求、角色/场景实体等。它们不一定都能由添加菜单直接新建。[实际UI或源码声明 S1]

| 产品层 | 类型/内部类型 | 作用与边界 |
|---|---|---|
| 基础媒体 | `rh-text`, `rh-image`, `rh-video`, `rh-audio` | 可以承载上传/现有产物，也可以承载生成任务；`subType/toolsType/modelCode` 决定执行能力 |
| 分镜/实体 | `rh-script`, `grid-preview`, `rh-role`, `rh-scene` | 结构化剧本、分镜格子、绑定角色/场景资产；实体不只是普通提示词 |
| 3D/导演 | `rh-w3d`, `rh-3d`, `rh-director` | 世界/网格3D、舞台/机位；可导出2D素材进入生成链；具体文件格式与3D模型服务见缺口 |
| 编辑/合成 | `rh-quick-cut`, `rh-video-compose` | 时间线编辑器与 Agent 硬切合成不是同一个能力面 |
| 复刻专用 | `rh-video-remake`, `rh-video-analysis`, `rh-remake-request` | 源视频、分析、修改要求和输出视频的专用路径 |
| 外部应用 | `rh-ai` | AI 应用由自身参数表决定输入/输出；不能套普通图/视频模型字段 |
| 结构元素 | `group`, `comment` | 布局、范围、注释；普通数据边校验会排除它们 |

## 2. 基础功能契约表

读表约定：T=文本，I=图片，V=视频，A=音频；数量“模型定”必须来自所选模型配置，不是所有节点统一上限。**M**=模型专属条件能力，**P**=主要是 prompt，**O**=prompt+预处理/编排，**L**=纯媒体/本地算法，**?**=尚未确认。O 不代表无需专业模型。证据列中D链接等同[官方文档]，S1/S2与明确源码条目等同[实际UI或源码声明]，Agent R编号等同[原站Agent自述]，问号/未确证等同[推测/未确认]。历史矩阵条目保留其原证据等级，未冒称本次生成实测。输出默认回到当前节点的结果/历史选择；“新增节点”“导出文件”“编辑器项目”单列。用户界面的“生成”与 Agent 工具调用、分组运行范围另见第4节。

## 3. 连线与输入装配：可验证的规则

### 3.1 数据边和运行控制分开

普通有向边表达上游素材/文本引用。[实际UI或源码声明 S1] 通常持久化 `source/target/sourceHandle/targetHandle`，默认手柄是 `output/input`；完整边对象可带 `data`，并非全产品只有source/target。Agent创建工具暴露的边只有source/target，这是较窄接口。[原站Agent自述 R1/R2/R5] 图上连线不等于立刻运行，不等于电影播放顺序，也不证明后端会自动补跑祖先。

前端 `Um` 禁止自身连自身、缺失节点、group/comment作为普通数据端点；`fy`检测同source/target重复边。`XSe`按目标 `maxConnect` 检查每种模态数量，导演台最多一个普通输入；模型配置决定更细的图片、视频、音频上限。[实际UI或源码声明 S1] 本次没有证明通用环检测，更没有证明系统支持循环。**不能把“禁止自连”扩大为“所有循环均检测”。**

主要普通连接许可矩阵如下；实际有效性还受模型/子类型/输出模态与maxConnect限制，不能据此承诺所有组合都能生成。AI应用/实体有模态归一化；导演导出、视频提音等是特殊路径。

| 上游 | 当前前端声明的可连下游 |
|---|---|
| 文本 | 文本、图片、视频、音频、视频编辑器、AI应用、3D世界、3D模型、脚本 |
| 图片 | 文本、图片、视频、视频编辑器、AI应用、3D世界、3D模型、导演台、脚本 |
| 视频 | 文本、视频、复刻、合成、视频分析、复刻请求、视频编辑器、AI应用、3D世界、脚本 |
| 音频 | 音频、视频、视频编辑器、AI应用 |
| 脚本 | 文本、图片、视频 |
| 角色/场景 | 文本、图片、视频、AI应用、脚本 |
| 视频分析 | 复刻请求、视频 |
| 复刻请求 | 视频 |
| AI应用 | 类型表列文本、图片、视频；最终按应用实际输出归一化 |
| 分镜格子/视频编辑器/3D世界/3D模型/导演台/复刻 | 普通出边表为空；不代表无法导出或通过专用按钮产生后继素材 |

例如导演导出有 `data.relation=director-export` 和 `mediaType=image/video` 例外；视频→音频有目标toolsType=`VIDEO_AUDIO`及sourceNodeId匹配的例外。合成只接受视频型来源。[实际UI或源码声明 S1]

### 3.2 多文本合并与优先级

当前单节点组包先用 `fv/sd` 依当前边数组顺序取得上游；文本节点 `fJ` 优先取非空 `data.text`，否则 `content`，然后转纯文本；其他文本输出有相应fallback。请求中prompt为：

```text
目标节点自身 prompt
上游文本1
上游文本2
所选预设展开的文字
```

各非空部分以换行拼接。[实际UI或源码声明 S1，约3361444附近] 若自身prompt非空，会过滤 `_isPromptTextNode` 或“agentCreated且标题以提示词结尾”的上游，避免Agent同时写prompt和辅助文本节点造成重复。脚本节点还会叠加全局stylePrompt。模型的真正prompt参数名按config解析，不总叫 `prompt`。

具体例：A=`红衣`、B=`蓝衣`、C=角色图，都连D，D自身prompt=`雨夜街道`。若普通A/B边顺序为A、B且无过滤标记，则请求包含 `雨夜街道\n红衣\n蓝衣`，再加预设；C进入图片引用。[实际UI或源码声明] **代码里未见颜色冲突的确定覆盖规则**；不能说“最后连接胜出”“自身prompt必定优先”。顺序是组包顺序，视觉冲突由模型处理，PF应在执行前消歧。[推测/未确认：模型具体取舍]

Agent在R2/R5明确表示其工具契约不知道这些前端字段。R5根据我们描述作条件推断，**不能作为独立佐证**；可靠依据是实际读取的客户端组包路径。

### 3.3 多媒体排序、首尾帧与选中历史

1. 上游非文本节点通过 `aNn` 解析真实素材URL；目标节点内嵌引用也参与；依 `nodeId:url` 去重。同URL但不同nodeId不一定去重。尚未上传的blob等临时来源不能直接当稳定引用。[实际UI或源码声明 S1]
2. `Mp`按 `imageOrder/videoOrder/audioOrder` 排序：优先匹配 `_key`、`nodeId::url`、URL或nodeId；未列在order中的素材保留，排在指定素材之后，保持原相对顺序。**order是排序，不是白名单筛选**。无order时保留收集顺序。
3. `tJ`依据所选模型的参数类型分派：第一图映射FIRST_IMAGE_URL/FIRST_FRAME_URL；存在至少两图时，**最后一图**映射LAST_IMAGE_URL/LAST_FRAME_URL；已消费素材不再填普通IMAGE_URL、IMAGE_PROMPT、SREF及额外图像槽，剩余再进IMAGE_REF/IMAGE_URLS（受maxNum限制）。视频/音频同样先单项槽、再动态槽/数组。因此“第一图一定是首帧”仅对声明该参数类型的模型成立，普通图生图不成立。
4. 用户历史选择由 `Wc`解析：先尝试selectedHistoryOutputId；也支持selectedOutputHistoryId+selectedOutputHistoryIndex定位历史输出；有效选中产物存在时，下游使用该产物，不一律取最新一轮。不存在时有当前output回退。不能把“一个节点的Agent产物契约”误写成整产品永远只有一张结果。
5. 角色/场景/道具语义可以由实体标签、Agent sourceNodeId、文本@素材用途等表达；通用边不会天然携带所有这些角色。动作模仿需要角色图+动作视频的专用能力，不能仅靠改变图片顺序替代。

这些是前端参数装配证据，未通过真实生成核对后端最终接受的payload、模型消费顺序或出图质量。

## 6. 典型用例与完整制作链

[原站Agent自述 R7，官方文档实战章节交叉支持] 主要是：①长期保存和迭代角色/场景/概念资产；②共享身份/场景参考的多镜头短片、广告、漫画；③人确认方向、选版本、局部返修后交付。画布保存可寻址资产与生成关系；聊天负责沟通和推理；ComfyUI一类工作流负责底层算子/模型计算；时间线负责确定时间顺序和音视频交付。它们可以组合，不能靠空间连线替代时间线。

一个剧本到成片的设计参考：

1. **剧本与分镜计划**：存文本和结构化镜号、剧情动作、对白、镜头、预计时长；LLM可辅助拆分，用户确认故事与镜头顺序。
2. **共享资产库**：抽取角色/场景/道具，生成或导入参考图，给实体稳定ID。用户确认外观和风格，之后镜头引用相同产物版本。
3. **镜头图**：每镜头一组prompt/参考/参数和可选历史输出；可以分批自动出图，用户挑选/返修。3D白模/画板/全景取景可以替代文字构图输入。
4. **旁白音画时钟**：若是旁白驱动内容，先确认文字/声音，生成一条主TTS，再检测静音拆出实测片段；视频长度以真实语音为依据。Agent例子“每秒约5字”只是规划估算，不能当精确时钟。
5. **镜头视频**：首帧、首尾帧或多模态参考按能力绑定；独立镜头可并行，连续镜头可显式抽上一条尾帧。完成后用户选版本；失败只返修对应分支。
6. **合成与剪辑**：按显式镜头列表硬切，或送时间线处理字幕、旁白/BGM、转场/封面与导出。Agent硬切接口只有视频列表，**没有证据证明主TTS切片会自动混入成片**，应使用音轨明确的编辑器/合成服务。

对“3镜头30秒”的例子，不应在TTS只有27秒或34秒时仍宣称精确30秒。需要调整语速/文案、视频时长、停留画面或时间线策略，作为可见制作决策。[设计建议；R4支持按实测时长校准]

## 7. PF必须理解的契约与建议顺序

以下是**设计建议，不是RunningHub内部字段还原**。现有PF应先按自身架构接入，不预设要建57张表。

| 契约 | 最少要表达的东西 | 原因 |
|---|---|---|
| Node | 稳定ID、工作面类型、功能子类型、配置/模型能力、用户/Agent创建、布局 | 类型不等于模型；编辑/生成/工具都可落在同一媒体类型 |
| InputBinding | 源node+outputId/版本、模态、role（character/scene/first/last/motion/audio等）、order、可选/必需 | 显式角色比依赖模糊连接顺序更可靠；切历史版本有可追溯影响 |
| PromptRecipe | 原prompt、模板/预设ID及版本、上游文字、实际组合文本、预处理参数 | 可以解释“这次为什么变了”，不把隐藏编排误当模型能力 |
| Artifact | 输出列表、稳定mediaId/URL、MIME、尺寸/时长/fps/alpha/3D格式、选中outputId、来源runId | 多结果与历史选择、音画计时、类型检查 |
| Run | 独立runId、输入版本快照、创建/提交/运行/成功/失败/取消，provider taskId、错误/费用回执 | 任务身份与产物逻辑身份分离；不重复提交、不虚报成功 |
| GraphRun | 明确范围、依赖拓扑、ready/blocked、并发预算、部分失败策略、重试/取消语义 | RunningHub后台未知的部分，PF必须自己定义，不照抄猜测 |
| Version/Dirty | 参数与输入变化的revision，保留旧结果，显式需重算标志 | 切源版本不暗中覆盖下游成片，重跑可控 |
| ReviewGate | 计划、参考资产、镜头版本、成片审批点；自动模式适用范围 | 人机协作的价值在选材/局部返修与状态透明 |
| Tool/Adapter | 接收的模态/角色/min-max/尺寸时长、输出类型、支持的专属能力、错误与取消 | 可替换供应商而不伪造功能支持 |

建议MVP顺序：

1. **P0 基础闭环**：T/I/V/A资源节点、持久保存与导入、显式引用与选中产物、可解释prompt合并、单节点异步运行/失败、上传下载、抽帧/裁切/拼接、分组整理。这一层应覆盖完整输入输出契约。
2. **P1 内容生产**：文本LLM/VLM、文生图/多图编辑、首帧视频、TTS、结构化脚本/实体/分镜、批量依赖调度与精确单分支重试；Agent先读计划再创建、先确认参考再生成。小时间线或显式音视频合成补齐交付。
3. **P2 专属创作能力**：mask编辑/抠图/超分、首尾帧、动作参考、音频驱动口型、素材预设库。能力由真实适配器确认后开放；姿态/多视角先做到输入可追溯。
4. **P3 工作面扩展**：实时画板、完整导演台/3D世界与模型、复杂复刻实验室、AI应用市场。应理解契约但不要求同时全实现。

同类开源模型可替换的条件是**输入角色、预处理、输出与运行契约匹配**：LLM/VLM、图像生成/编辑、mask/pose、I2V/首尾帧、多模态/动作、TTS/音乐/lip-sync、3D分别验收。不要承诺一个通用图像或视频模型覆盖全部。纯媒体算法也应独立。此轮不推荐具体开源权重、不声明许可证/显存/性能；RunningHub文档里的模型营销描述不能替代上游项目model card与部署验证。

## 8. 冲突、缺口和验证界限

- Agent自述只有5类生成节点；实际菜单10类、源码17类内部节点+结构元素。这是接口可见性差异，不能用Agent列表代表全产品。
- Agent说文本节点只是持久文档、音乐/歌词/对口型未知；官方正文与前端/历史矩阵反证存在相应产品路径。本报告采用更强可见证据。
- 官方“深度视差”称深度估算/三维重建，“动态场效”称动态粒子，但已有矩阵F087–F093显示相关入口是image-image+sceneCode→图片结果，尚无深度张量/3D层/动画输出证据。按图像场景预设对待，真实专用算法未确认。
- 官方动作复刻教程写≤15秒，旧UI矩阵写≤30秒；当前限制应读取具体入口与模型配置，不能择一当全产品统一限额。
- 官方多处“100%一致”“完全物理正确”“无限并发”“无成本”等未实测，不纳入产品保证；本次没有检测成片品质、性能、价格或额度消耗。
- 文档嵌入的视频教程未逐个播放；部分嵌入表格为canvas，无逐格文本导出。已读正文不等于完整观看全部媒体附件。详情见覆盖文档。
- 未确认：后台拓扑/循环/并发；祖先补跑与缓存；失效和失败级联；真实取消；计费去重；mask/骨架张量；完整3D服务格式；音色克隆执行端；Agent总音轨自动混音；多人同时编辑冲突解决。
- 所有“真实输入字段”只来自本次公开前端、过去已记录目录/XHR或Agent自述；没有探测隐藏接口/后台系统指令，没有复制整套官方文档/编译源码进Git。

## 9. Agent桥接能力与最小补证方案

[实际UI或源码声明 S2] 当前host声明15类能力，普通canvas-main使用其中14类，one-click-remake额外有video-analysis.update.v1。它们与55个产品功能契约行是不同粒度：

| Host capability | 对应职责 |
|---|---|
| canvas.read.v1 | 只读画布、节点、边与产物状态 |
| workflow.create | 创建节点/边/分组计划，可另指定autoRun |
| node.update / node.delete | 修改/删除已有节点 |
| group.create / group.modify | 分组及成员调整 |
| node.run / group.run | 提交已有节点或分组运行 |
| layout.relayout | 自动布局 |
| video.compose | 有序视频硬切合成 |
| video.frame.extract-last | 已完成视频抽尾帧并建立素材 |
| image.stitch.vertical | 有序图片竖拼 |
| audio.master.create / audio.master.split | 主TTS与真实音频分段 |
| video-analysis.update.v1 | 复刻流程的分析信息更新 |

这不是后台隐藏工具全集；图像分析、Skill加载等Agent内侧行为未全部作为host能力暴露。当前聊天LLM也没有独立用户可选菜单，生成偏好主要是图像/视频模型。[本轮UI、已有工作模式研究]

以下是**后续验证设计，不是已执行工作**。若以后要实测，只能在独立临时研究项目，明确费用上限并保留真实回执，不能在用户作品上试验：

| 未知 | 最小可验证条件 |
|---|---|
| 祖先补跑/组调度 | 已上传A、未运行B、依赖B的V；分别保存node.run与group.run请求/事件/最终节点状态，对照是否自动等待/补跑 |
| 缓存/失效 | 固定B的输入版本运行一次；仅切A所选历史后观察dirty/回执，再比较显式重跑的runId、计费和产物ID；不能只看画布缩略图 |
| 失败与部分成功 | 通过受控无效必填项产生校验拒绝，区分提交前拒绝与真实任务失败；只重试该节点，验证其他ID没有重建 |
| 取消 | 已提交可取消的短任务，记录取消请求、provider最终状态和费用回执；聊天停止按钮不算证据 |
| 端口/骨架/mask | 只读已配置的工具schema与提交前表单，再看可公开请求里的角色/选区表示；无权访问的服务端参数不探测 |
| 总音轨到成片 | 用已备好的可用音频/视频，查看合成输入是否真的包含切片/混音时间线；仅有videoNodeIds不足以证明旁白被混入 |
| 循环/并发 | 先验证前端是否阻止A→B→A；服务端并发需独立受控任务和时间戳，不从“无限并发”文案推断 |

当前研究已到达公开证据的合理边界，继续让同一个Agent猜测不会提高可信度；PF可以先定义自身明确契约，再按上述项目验收。
