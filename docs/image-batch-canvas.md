# 图片批次与独立画布节点

实现范围：Codex 文生图/参考图生成 capability version 2；原生界面选择 1、2、4 张，单次点击提交一个画布任务。Router 在同一 Codex turn 内通过版本化执行指令请求多次原生生图调用，按完整终态回执收集图片。数量不是原生工具的 `n` 参数，也不保证底层并行。

完整成功时，首张回写原图片节点，其他图片分别建立相邻的图片节点。原节点仅展示首张，完整结果仍保存在原任务历史中。结果节点各有一张图片和自己的资产引用，可独立接线、移动或再次生成；`batchOrigin` 记录来源任务、执行、原节点和输出标识。

单节点执行的新节点使用确定性标识，在任务保存事务内与画布一起提交。已应用任务的重放不会重复建节点。原节点或输入在执行期间改变、被删除或执行被替代时，保留任务结果但不向当前画布插入旧结果。画布节点数与体积上限仍生效。

分组/整画布执行沿用客户端回收路径，也按每张图片拆分；通过当前任务归属、确定性节点标识和持久投影标记避免重复插入。已经移动、修改或删除的结果不会在后续轮询时重新覆盖或创建。批次关联同时保存在原生保存白名单允许的 `historyStorage.imageBatchOrigin` 中；子节点不携带原节点的 `historyId` 或远端历史选择权限。

version 2 的失败/取消回执可以带有已经验证的图片。STUDIO 导入这些真实结果并分别创建图片节点，保留原任务失败/取消状态，不继续执行依赖步骤、不自动重新生成。此类图片可从画布和任务输出访问；现有成功历史列表仍只收录成功批次。

历史 version 1 继续按其单张 schema 回放；编辑提示词不会静默升级已保存的版本。选择当前新模型能力后可使用多张参数。

验证包括前端原生 4× 只提交一个任务、旧版参数保留、独立节点预览与输入解析，以及执行 worker 部分结果导入、PostgreSQL 原子写回、重放不重复、子节点输入隔离和过期结果保护。
