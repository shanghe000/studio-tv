# Studio TV 内部共享与协作设计

日期：2026-10-07。设计基线：3e1efe9。设计提交：0107b17，先于实现。状态：IMPLEMENTED，隔离测试和浏览器验收已通过，已发布至 deployment-host；版本及上线检查见末尾发布记录。

## 1. 授权边界

IPAC 负责真实飞书身份、会话有效性与整个应用的 `tv.access`。Studio TV 继续复用现有最长五分钟的 IPAC 授权租约，不注册项目、团队或资产级 IPAC 权限，也不为每次成员操作调用远程鉴权。

Studio TV 在 PostgreSQL 中管理项目协作者、团队成员和资产共享。每次资源请求都检查本地权限。应用准入和资源权限必须同时满足：IPAC 撤销应用使用权时，STUDIO 内部成员关系不能成为登录或访问的替代途径。

真实调用者始终是登录账号。项目所有者是资源归属，不能将协作者的登录 UID、会话或 Bearer 换成所有者。复用现有按 owner 存储的模块时，必须先针对明确的项目/任务/资产进行授权，再使用该资源的存储 owner；不能把这一 owner 扩散到个人资产库、其他项目、全局聊天或账户接口。

## 2. 本期产品行为

### 项目共享

- 原有项目默认私有，现有数据不自动共享。
- 所有者添加已在 Studio TV 通过飞书登录的用户，授予 `EDITOR` 或 `VIEWER`；也可将项目共享给一个自己有权使用的 STUDIO 团队。
- 所有者管理成员、团队授权及删除项目。编辑者编辑画布、更新项目名称/封面、上传项目素材、执行已接入的节点功能。查看者只读取项目、画布及其媒体，不提交修改或生成任务。
- 项目列表展示本人项目与被共享项目，明确显示当前权限。共享链接只是内部项目地址，接收者仍需登录并具有成员权限，不提供匿名或公开分享。
- 成员列表可查看、改角色、移除；最后的所有者不能被移除。本期不提供所有权转移。

### 团队与团队资产

- 默认方案是在 Studio TV 内创建团队，由团队所有者添加成员；团队身份不映射为 IPAC 工作空间，不建立伪用户。
- 团队角色为 `OWNER`、`EDITOR`、`VIEWER`。所有者管理成员；编辑者可发布/维护共享内容；查看者只读取与使用共享内容。
- 团队资产库独立于个人资产库。已有个人资产只有经过明确“发布到团队”操作才进入共享库。
- 共享条目保存真实素材/节点数据，不能把 SYSTEM 公共目录或空数组当作团队数据。发布时校验发布者对所有引用素材的权限与 READY 状态。
- 向项目导入团队资产时创建该项目的真实副本并改写素材引用；既有项目引用不依赖发布者的个人目录。明确显示：导入后的项目副本不会因团队条目删除而消失。
- 团队成员移除后，不能继续枚举、修改、下载团队库的源条目。已合法导入且仍有权访问的项目副本按项目权限管理。

### 协作同步

复用现有服务端快照、增量事件、三方草稿合并与强 ETag。不同成员能够看到同一项目的已保存更新；不同字段可以按现有合并规则同步，同一字段冲突暂停保存并保留草稿，不覆盖另一成员的修改。本期不宣称提供 CRDT、在线光标或逐字共同编辑。

## 3. 权限矩阵

| 操作 | 所有者 | 编辑者 | 查看者 | 非成员 |
| --- | --- | --- | --- | --- |
| 项目详情、画布、项目媒体与执行结果 | 允许 | 允许 | 允许 | 404 |
| 保存画布、改名称/封面、上传、节点生成 | 允许 | 允许 | 403 | 404 |
| 项目成员管理、共享给团队、删除项目 | 允许 | 403 | 403 | 404 |
| 团队详情、共享条目读取/导入 | 允许 | 允许 | 允许 | 404 |
| 团队共享内容写入 | 允许 | 允许 | 403 | 404 |
| 团队成员管理、删除团队 | 允许 | 403 | 403 | 404 |

项目有效角色取直接成员与团队授权中的最高权限。团队查看者即使团队获项目编辑授权，也只能查看。账号停用、团队/项目删除或应用使用权撤销始终拒绝。

## 4. 数据与兼容性

新增独立 `collaboration` schema：团队、团队成员、项目直接成员、项目团队授权、团队资产条目/引用和审计记录。约束包括真实用户/项目/素材外键、唯一成员关系、合法角色、软删除及递增 revision。

保留旧项目、资产、个人文件夹和库条目的 owner。团队不使用 `owner_id` 冒充账号。新增发布与导入记录保存发布人/导入人，不重绑定旧数据。

项目授权必须覆盖项目引用媒体。素材读取不能仅检查“调用者与素材 owner 相同”；对于协作者，需要检查该素材是否属于可访问项目或被该项目实际引用，避免凭任意资产 ID 查看所有者的其他私有素材。保存/执行输入同样检查引用范围，不允许编辑者注入所有者另一个私有项目中的素材。

模型任务与画布的存储归属、实际发起人必须区分；审计与上游调用记录实际发起人。全局 Agent 会话保持个人归属；项目绑定会话只在明确项目权限下操作，不能通过项目共享读取所有者的全局聊天。所有权限变更、发布及导入写入本地审计，日志不包含令牌或媒体签名 URL。

所有写入使用数据库事务。项目资源修改与成员撤销以同一项目行锁协调；撤销提交后，新请求必须拒绝。团队写入与成员变更同样协调。成员和共享内容更新使用 `If-Match`，缺少条件返回 428，过期返回 412。幂等键按真实调用者与操作范围区分。

签名媒体令牌绑定实际请求者的账号和会话，并在每次读取时重新检查本地资源权限；旧链接不能绕过成员移除。SSE 除原有身份重验外，还需定期检查本地项目成员关系并结束已撤销的流。

## 5. 接口和前端

冻结 v1 合同及原生编译资源继续保持不变。新增能力放独立 `/api/v2` 协作扩展，提供：

- 已注册可添加用户搜索（最小显示字段，不暴露邮箱、手机号、IPAC 凭据）；
- 团队列表/创建/详情、成员列表/增删改；
- 当前用户可访问项目及有效权限、项目成员管理、团队授权；
- 团队资产列表/发布/更新/删除、导入目标项目；
- 本地权限审计。

原有项目/快照/素材接口通过明确资源授权接入协作，既有个人功能保留。未知接口仍 404，未接入功能仍 501，不新增成功兜底或模拟数据。

自有 TypeScript 层提供“协作成员”“与我共享”“团队管理/团队资产”入口及成员面板。查看者有清楚的只读提示，并禁用修改/生成控件；后端仍独立强制只读。角色和成员列表用返回的实际 revision/权限呈现，错误时显示失败，不回退到个人库或空团队数据。保留页面跳转、返回和前进；成员变化后刷新本地权限。

## 6. 验收标准

使用隔离 PostgreSQL 和至少三个真实测试身份，在正式数据之外验证：

1. 所有者、编辑者、查看者和陌生人完整的读取/写入矩阵；非成员不能凭猜测 ID 读取。
2. 成员添加、角色调整、移除、团队授权以及 revision 冲突；撤销与保存并发时没有越权提交。
3. 共享画布读写、快照/事件同步、双成员保存冲突、项目媒体上传/下载和任务结果；全局聊天及其他私有项目保持隔离。
4. 团队资产发布、列表、读取、导入、真实字节一致与引用重写；移除成员后旧媒体链接失效，项目独立副本仍有效。
5. 后端拒绝查看者的直接 HTTP 写入；前端显示真实只读态及成员操作失败。
6. IPAC 仅出现应用级授权，无新增项目级远程检查；应用权限撤销仍生效。
7. 迁移可从现有库升级并重复执行，旧项目/素材不被共享、移动或丢失；1198 个原生资源字节校验继续通过。
8. 构建、类型检查、相关单元/数据库集成测试和浏览器交互验证通过后，再发布。测试模型使用既有显式测试路径，不为权限验收调用收费模型。

正式环境只有一个已登录飞书身份时，不能伪造另一个生产用户或绕过 IPAC 来宣称真人多人验收；应报告隔离测试覆盖及尚需真人参与的边界。
