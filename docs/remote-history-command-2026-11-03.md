## 证据与原因

日志 `f1d0d45a-0f68-4c11-84eb-99401d7a82e0` 在提交前返回 `STALE_EXECUTION_INPUT`，比较阶段为 `inputs.command`，组件为 `HISTORY`，目标为 `h3-video-reference-v1` 版本4。它没有产生 task 或 execution。只读核查时，该目标已有远端历史指针、一个本地历史缓存条目、四种选择字段及一个旧视频结果；不读取或记录用户提示词、媒体地址。

冻结原生 `q_/MCe` 先保留这些历史字段；提交前 `W8` 遇到 `source=remote/schemaVersion=1` 的历史记录，会原样保留显示输出，规范化历史指针，并省略 `nodeOutputHistory`、`selectedOutputHistoryId`、`selectedOutputHistoryIndex`。它保留 `selectedHistoryBatchId` 和 `selectedHistoryOutputId`，不修改画布或执行历史选择回写。

原适配层仅恢复空本地缓存，未覆盖有历史条目时的上述合法省略。因此真实原生函数链可复现正常重新生成被误报为历史输入不一致。日志里的 sourceNodeId 等于生成目标，只表示字段归属，不表示自环连线。

## 修正与保护

图片和视频复用同一远端历史省略恢复函数。只从任何异步等待之前捕获的节点恢复上述三个缺失字段；要求模型与版本、完整远端历史指针、显示输出、媒体字段、两个保留的远端选择字段均相同。图片已有的批次来源省略兼容继续按原历史身份验证。

命令显式提供空数组、null、不同缓存或不同选择值时不覆盖。改变历史ID、版本、结果数量、媒体或保留的选择ID时不恢复。源节点不使用此修复。原有完整命令比较、节点身份、版本、保存回执以及所有异步等待期间的画布输入检查继续执行，不用更新后的远端状态重建旧命令，也不忽略真实历史选择。
