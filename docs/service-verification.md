## Ego 浏览器实际流程

使用 ego-browser 的同一个验收 TaskSpace 检查 preview 与 service。服务页通过 SSH 转发至 `http://localhost:18880`。

1. 新建项目触发原生登录窗口；提交真实邮箱/密码成功，服务端生成项目 ID 后进入画布。
2. 添加文本节点，双击原生编辑器输入内容；自动保存产生新 revision。
3. 刷新恢复登录和文本，保留节点位置、尺寸及原生 data。
4. 原生“添加资源→上传→上传文件”导入 PNG；经 init/PUT/complete 在服务端进入 READY，再创建图片节点。
5. 刷新后，持久化的完整图深比较一致；素材以 `rhtv-asset:` 引用保存，读取时重新签名。经 Nginx 的 Range 请求返回206和正确8字节。
6. 拖动文本节点标签改变位置，原生撤销快捷键恢复位置，并再次保存。

版本提示组件检查为 `aria-hidden=true`、opacity=0，与原生默认行为一致。快照工具会列出其隐藏文字；不是新出现的可见提示。

## 具体边界

本轮完成服务基础与核心持久化。未声称恢复原站 TSX 组件源码；也未进行所有动画的逐帧像素比较或全部功能选项的完整验收。截图捕获在此浏览器画布上发生 CDP 超时，本轮浏览器证据使用原生控件操作与实际数据/HTTP结果。

模型供应商未配置，四类能力均未联网。团队、支付、共享、协同、素材库写操作、3D资产、HyperFrames服务器执行仍为 RESERVED；目录是只读采样。公开域名/TLS、定时备份、清理废弃文件、正式运维监控仍属于后续部署步骤。详细边界见 service-boundaries.md。

测试账号密码与数据库/签名密钥均保存在 Git 外的私密配置，验收记录不包含这些值或临时签名URL。
