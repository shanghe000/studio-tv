# Studio TV 的 IPAC 授权边界

Studio TV 在 IPAC 注册为一个中台应用，只接入真实飞书登录和唯一工具级能力 `tv.access`。TV 沿用原有页面布局、画布和功能，不展示或选择工作空间。IPAC 的项目、环境与角色只在授权后台管理；画布作品 `projects.id` 是本地作品 ID，与 IPAC 项目 ID 无关。

本文按用户本次要求替代旧工作空间设计。代码 `8be955f` 已部署 deployment-host，本轮证据及待完成项见 [工具级授权发布记录](ipac-tool-access-verification.md)。[0.3 发布验收](ipac-verification.md) 保留当时的真实结果，其空间界面及分区规则是历史记录；旧版生产撤权/恢复实测不计为本轮实测。

## 已实现的范围

按 2026-10-07 用户降低请求频率、放大权限粒度的要求，授权单位统一为整个应用的 `tv.access`。后端从已验证本地会话取得可信 IPAC issuer、subject、sid 和 session_version；官方 SDK `EffectiveScopes` 返回 ACTIVE 的主体/应用、匹配版本及包含精确 `tv.access` 的非空项目环境范围时，即可授予整应用访问权。该响应已经按 IPAC 的真实有效角色、范围与能力求值，不再逐范围调用重复的 Runtime `Check`。登录成功本身不授予权限。

浏览器不请求工作空间列表、不传范围选择参数。旧 `GET /api/v1/workspaces` 路由退役并返回通用 404；本轮不提供 `/api/v1/authz/workspaces`、其子路径或授权自查端点。`X-Workspace-Id` 退役，后端即使收到也完全忽略，不影响授权、资源查询、保存、引用或幂等结果。浏览器不能自行指定 IPAC 身份或范围来取得权限。

作品、画布、素材和上传仍按本地 `owner_id` 隔离，不按 IPAC 项目或环境分区。同一 owner 的既有作品和素材不因旧空间值不同或为空而被排除或禁止引用；空空间不再返回 `WORKSPACE_UNASSIGNED`。应用管理员也只能处理本人作品和素材。本版没有团队协作、跨用户管理员旁路或本地角色兜底。

既有映射表、`workspace_id` 列、非空值及 NULL 原样保留，不删表、不清空、不重分配，也不再参与业务隔离。身份仍只按可信 `(issuer, subject)` 关联，不按同名或同邮箱合并旧密码身份，作品 owner 不自动转移；本版没有历史认领 API。

## 能力与角色

当前只登记一个能力 `tv.access`（使用 Studio TV）。作品列表、创建/编辑/删除、画布读写、素材读写/删除及签名 GET/HEAD/PUT 都检查该能力，不提前细分按钮或功能权限。

IPAC 的非游戏业务项目 **AIGC** 已开通 Studio TV 的应用权限环境；维护者为管理员。该角色只包含 `tv.access`，在真实 AIGC 项目/环境范围内绑定。此范围是后端访问 IPAC 时使用的授权依据，不是 TV 作品的数据分区。服务端不按角色名称或本地用户名称给予管理员旁路；撤销该能力、人员、应用或范围后，最迟在现有五分钟租约到期后的请求生效。

本轮没有修改 IPAC 的应用登记、能力、角色、人员或范围分配，也没有更新其源码和运行部署。无权、过期、版本失效、上游故障、伪造空间头及跨用户访问由本轮隔离自动测试覆盖；没有在当前生产权限上再做撤销/恢复操作。

能力清单在 `contracts/ipac-capabilities.template.json`，应用代号必须替换为实际 `IPAC_APP_ID`。SDK 内部 `authorization.ManifestDocument` 生成同一完整快照；先 Preview，再 Submit，最后由 IPAC 管理员审核生效。API 启动不会提交或自动批准清单。冻结的核心 v1.0.0 合同没有修改；工具访问策略、既有路由权限及退役实验接口见 `contracts/authz-extension.json` 与 `.yaml`。

LLM、文生图、图生视频、全能参考和协作功能继续保留未实现接口，返回原来的 501，不执行模型或计费。本次不提前给未实现功能赋予可执行权限。

## 会话与媒体撤权

每次业务请求仍验证 Bearer 的本地签名、期限、数据库会话及账号状态。日常 SessionStatus 和应用访问决定各自缓存最长五分钟，分别绑定可信身份、上游 sid、版本和应用；有效期不得超过上游或本地会话期限。首次访问/租约过期才刷新 IPAC，同一键的并发请求合并，单个调用者取消不会取消其他等待者的刷新。登录和 refresh 强制实时验证上游会话。服务重启清空租约，不持久化凭据或授权缓存。

session_version 不一致或上游会话失效时撤销本地会话并返回 401；没有任何可用 `tv.access` 返回 403；网络、协议或上游授权故障返回 503。错误只短暂合并两秒，不延长已过期允许，不采用 stale-while-revalidate。

素材读链接与上传链接除资源 ID、用户 ID 和签名外还绑定签发时的本地 `session_id`。每次 GET、HEAD、PUT 都重新验证该会话、资源 owner 及工具级 `tv.access`，复用同一应用授权租约，不从旧空间列派生权限。旧的无会话签名也不能使用。媒体响应与错误均 `no-store`；禁止通过浏览器缓存维持撤销后的访问。

本地退出/撤销及账号停用在下一次请求立即生效；IPAC 的权限、人员、范围或会话撤销最多五分钟生效；已经通过检查并开始传输的请求可以完成，已下载的字节无法收回。上传完成接口仍会再次检查授权。签名 15 分钟过期上限不延长五分钟授权租约。发起续期会替换上传 grant，使旧 PUT 签名失效。

## 配置

授权使用同一 `IPAC_APP_ID` / `IPAC_APP_SECRET`；`IPAC_BASE_URL` 未配置时使用 `IPAC_ISSUER_URL`。默认要求 HTTPS；本地开发使用 HTTP 必须同时显式启用 `ALLOW_LOCAL_HTTP` 与 `IPAC_ALLOW_INSECURE_HTTP`。Secret 只由私有部署环境注入，不进入清单、前端或日志。
