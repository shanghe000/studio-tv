# 原生模型入口梳理

2026-10-06。按页面和原生 UI 家族合并梳理，细分场景、207 个功能坐标及原请求证据见 [model-function-matrix.md](model-function-matrix.md) / [配套 JSON](model-function-matrix.json)。既往在 deployment-host 验收首页、画布助手、带图对话、图片解析及原生媒体菜单；表中其余“待验收”项仍需按按钮逐项核对，不代表全部功能已真实调用。

工作方式/模型纠错与工具缺口见 [完整核对](modes-and-agent-integration.md)，纯文本及实际原站 LLM 目录见 [替换核对](text-llm-replacement.md)。原站模式菜单只有四项；此前插入 Codex 型号及随后增加的 Agent 聊天型号控件都不属于原站界面。本轮按仅替换原模型名字的要求移除额外聊天控件；无原生 LLM 菜单的入口使用后台默认。

当前真实目录提供 Codex 5.6/6/6.1 文本、6/6.1 图片理解；STUDIO 不提供5.6图片理解 profile，当前没有真实 VIDEO 理解。媒体生成、编辑、音频及 3D 仍为明确 TEST MODE，真实配置尚未接入；不能重命名后称为真实模型。已验收的历史结果见 [router-real-integration.md](router-real-integration.md)，不自动推广至全部功能。

## LLM固定旧代码的严格映射

这些代码来自已验证原生回调，需要按**功能+实际输入+输出协议**识别；不能把任意未知 modelCode 回落到默认型号。最终仍提交真实 capabilityRef/version/schema 并由后端校验。其它媒体固定代码/默认表/全景白名单及应用ID兼容详见 [完整矩阵](model-function-matrix.json)。

| 固定代码 | 原入口 | 必需的功能边界 |
| --- | --- | --- |
| `llm-haimaflash-multimadal-text` | 图片“解析”→文本节点 | 按图片解析功能精确绑定图片理解，保留原图与原提示模板；默认6.1 vision，纯文本选择不能覆盖 |
| `llm-gemini35flash-image-regecognition2000` | 图片局部元素“识别” | region-recognize + IMAGE + point/bbox协议，不能普通LLM任意代替 |
| `llm-haimaflash-image-regecognition`；导演另按 `google-gemini-3-5-flash` sku/name查找 | 默认图层拆分、导演文字/图片识别 | 分别按层识别/导演布局feature及实际TEXT/IMAGE映射，保留JSON schema；后续抠图/填补还需真实媒体能力，不复制原无目录fallback |
| `canvas_prompt_user_style_extract` | 风格参考图提取 | IMAGE + 专门style-extract模板；`user_style_extract_prompt`是服务模板标识，不等于完整提示词 |
| `google-gemini-3.5-flash`（点号版本） | 助手 `make_hit/action_clone` 技能视频预分析 | 必须VIDEO能力；目前无真实支持时明确未接入，不映到text/vision、不丢弃视频；不是全部Agent操作的固定模型 |

原生视频优化型号关联 `promptEnhanceModelCodes` 要与真实目录能力一致；原站可临时合成裸alias/config的实现不能当作可用性证据。既有用户选择未知、失效或不兼容时必须拒绝，不能静默更换模型。
