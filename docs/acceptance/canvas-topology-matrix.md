# 连线与二次生成：计数和逐项对照

统计时间为 2026-11-04。不要把“能连接”“满足生成条件”“运行成功”相加或互换。节点、具体素材、提示词和重复编辑次数没有一个可供穷举的固定总数；下文使用明确、可复跑的有限口径。

## 1. 端口是否允许尝试连线

冻结编辑器的 Bm → lpn/JQ 检查 **17 个基础类型、289 个有向类型对，51 允许、238 禁止**。类型相同代表不同的两个节点；连到自身、重复边、循环、悬空、错误端口仍会拒绝。分组/批注不是这 17 种内容类型的输入端；应用结点已产出具体模态时，原生 Hd 会把它映射成实际模态再检查。表中仅是端口的能力，**不能由此推断真实服务、模型或特定工具已开通**。角色、场景和实体作为图片上游时，冻结编辑器会把命令中的三种来源临时归为图片；服务保留原节点类型，只接受当前直接连线及其显示的素材。三种来源分别经原生命令、前端适配和接收端回归。

## 2. 编辑之后，模型实际收到了哪些输入

[逐项 CSV](canvas-topology-matrix.csv) 一行对应一个“操作、A 类型、B 类型、模型和版本”；assetIds 为最终候选图上应被消费的素材身份（分号分隔；跨模态仅按模态内顺序定义角色）。A/B 各自取文字、结构化脚本、图片、视频、音频五种；A、B 的素材身份独立，B2 是重建后的新身份。**28 个当时标注可用的非测试模型 × 5 × 5 × 11 = 7,700 行**。两个历史 agent 目录项也计入模型行，不等同当前菜单默认模型。另 36 个需个人密钥的视频配置及 20 个 mock 不混入此矩阵。视频超出两个素材后的数量边界另见[数量矩阵](canvas-video-counts.md)。

|序号/操作|就绪|缺少必需输入|禁止（端口/类型/数量）|目标不存在|
|---|---:|---:|---:|---:|
|1 新目标接 A|190|250|260|0|
|2 断开 A|250|450|0|0|
|3 重接 A|190|250|260|0|
|4 断开 A 换 B|190|250|260|0|
|5 删除 B 源节点及邻边|250|450|0|0|
|6 新建 B2 并接入|190|250|260|0|
|7 删除目标及邻边|0|0|0|700|
|8 新建目标并接 A|190|250|260|0|
|9 保留 A，追加 B2|158|133|409|0|
|10 保留 B2，断开 A 再接 A|158|133|409|0|
|11 控件明确指定 A 优先|158|133|409|0|
|合计|1,924|2,549|2,527|700|

所有行均以默认合法参数、已就绪且尺寸/时长合规的唯一素材、已填写（或模型忽略）描述为前提。一次候选编辑无需满足最低参考数量；缺素材时允许继续搭图，生成必须拦住。禁止步骤按候选图检查，用户正常拖线时不会先保存非法边；已导入的不合理组合也不能生成。删目标后没有提交对象。第四、六、八步的单素材数量相同，但源/目标身份不同，并独立核对，不能沿用“数量没变”就判定输入没变。首尾帧依当前同类连线先后或明确排序分配；仅改变节点创建/显示顺序不应换帧。两条边引用同一物理资产、同图多角色和历史资产权限是额外边界，未把它们算成两份不同素材。

## 3. 复跑与证据边界

在仓库根目录执行：

```sh
STUDIO_CANVAS_AUDIT_EXPORT=/tmp/studiotv-topology-run npm --workspace @studiotv/web exec -- vitest run --config vitest.config.ts canvas-topology-matrix.test.ts
```

测试使用服务的 84 项[脱敏能力样本](../../tests/web/fixtures/canvas-catalog-audit-20261104.json)、冻结原生端口表、实际节点/边操作 reducer、连线校验和 ExecutionAdapter 的生成准备。用独立的预期边序和模型最小/最大数量表核对全部状态，不构造“后端已成功”的结论。导出 `-matrix.csv`、`-counts.json`、`-requests.jsonl`（所有 1,924 条就绪行捕获的 canvas-runs 请求体，含 1,316 条图片/视频、608 条文字/视觉）和 `-timeline.jsonl`（三个代表模型各11步、包括不提交步的完整操作流）。生产任务和供应商计费不是该测试的一部分。后端额外验证请求正文对历史输出的授权、去重、条件角色，以及执行工作线程绑定时的顺序。真实服务边界验收与静态枚举应分开报告。

额外测试角色、场景、实体三种图片来源，不将其与上面 1,924 条相加计算通过率。使用冻结编辑器实际的 `q_` 和 `W8` 函数生成命令；它们临时把这三个来源投影为 `rh-image`。前端执行器只能将当前直接连线上的同一来源还原成实际类型。三个样例均验证已生成过的视频再次运行时不会把其旧视频当作新参考；独立对三条实际 HTTP 请求重放，生成接收端均收到显示中的唯一素材 `a-image`。在仓库根目录导出并复播：

```sh
STUDIO_CANVAS_ALIAS_EXPORT=/tmp/studiotv-alias-requests.jsonl npm --workspace @studiotv/web exec -- vitest run --config vitest.config.ts execution-video-connections.test.ts
python3 scripts/test-canvas-boundary.py /tmp/studiotv-alias-requests.jsonl --out /tmp/studiotv-alias-boundary --jobs 1
```

复播使用该驱动的隔离 PostgreSQL 环境；输出目录中的 `results.json` 记录每条请求与生成接收记录的校验结果。

## 4. 在真实 STUDIO 服务连续编辑并走到生成请求接收端

另用隔离 HTTP 服务、真实鉴权/编辑会话、PostgreSQL、工作线程，运行正式前端 ServiceStorage 和 ExecutionAdapter。只有生成接收端使用合成返回，不调用收费模型。没有修改试用用户的画布。每次都从服务端读取已经写回的成品，再编辑同一个节点；服务端记录的执行 ID 与接收端记录一一对应。

- **两种单目标各测三次。** 图片编辑和视频全参考先取 A；断开后不能提交、成品和历史都保留；连接 B 后二次生成；删 B 同样不能提交；重建 B 的素材已换成 B2，再次生成。六次成功回写对应六份接收记录，接收端实际收到的唯一素材依次是 A、B、B2。四次缺料没有创建任务。
- **一张跨文字、图片、视频与动作迁移的分支图。** 文本与图片 A 生成左图，A 同时生成独立右图；左右两个真实生成结果汇合生成首尾帧视频，左图也连到单独的视频节点。显式反转首尾帧并再次运行，接收端首帧/尾帧的资产身份与新顺序一致，旁支视频成品没有变化。
- 删除中间左图后，这两个有历史的下游都在提交前停止（未创建任务，之前的成品保留）。将新图片 C 接入两处并重新生成；保留的右图换源为 B、生成新结果后，汇合视频只消费右图的新成品和 C，不含任何已断开的 A、B、旧左图或旧右图。最后选择右图的旧历史再生成，接收端确实取到旧右图、而保留的右图最近执行记录仍是新的一次。这十次成功回写逐个核对了输入身份、顺序和首尾角色；两个缺料步骤零任务。

- 继续在同图添加动作迁移：把旁支生成的视频和图片 A 连接到运动节点，断开视频触发拦截，换成汇合视频后再生成。对上游汇合视频执行二次生成，再分别选择最新和上一条视频历史继续动作迁移。生成请求中的人物图、动作视频分别是预期的 `REFERENCE_IMAGE` 和 `SOURCE_VIDEO`；移除素材不会隐式引用旧视频。深图合计 **18 步，15 次送达并成功回写、3 次未提交**；与上面普通单目标流程合计 **28 步、21 次送达、7 次拦截**。

复跑驱动：[live-topology.ts](../../tools/canvas-router-audit/live-topology.ts)。须使用配置了合成回写与请求记录的**隔离回环服务**；驱动拒绝非回环地址。在仓库根目录以 esbuild 将驱动打包到临时目录，设置 `STUDIO_CANVAS_FIXTURE_DIR` 指向运行夹具目录。默认运行单节点连续二次生成，`STUDIO_CANVAS_COMPLEX=1` 运行多层分支及动作迁移图。也可使用 `python3 scripts/test-canvas-boundary.py --live --out <新的证据目录>` 自动运行两条链路。分别生成 `live-topology.json` 和 `complex-topology.json` 账本（逐步结果、历史、期望/接收的素材和角色）。这些实测结论不代表真实供应商始终在线、模型输出效果或所有编辑历史都已实跑。
