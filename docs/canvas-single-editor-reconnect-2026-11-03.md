# 单人断开连线、重连与保存排查（2026-11-03）

## 原始问题与证据边界

用户反馈：单人打开已有画布，删除视频的前置连线后重连，出现剪贴板占位说明和暂停自动保存提示。线上项目只读排查，没有修改用户图、提交模型任务或刷新其原页面。

服务端最后成功保存和当前图能说明服务器收到过什么，不能还原浏览器中未提交的操作。以下缺陷分别由真实冻结函数回归、完整原生画布操作确认，不把多个独立缺陷武断地归为同一个生产请求的唯一原因。

## 已定位缺陷

1. 节点占用确认前拦截鼠标后，原实现把 move/up 重放到 window。冻结 ReactFlow 连接处理器监听 document，因此错过结束与清理；占用确认前已经完成的拖拽也被丢弃。现在从实际 DOM 目标冒泡到 document/window，并完整补放等待期间的移动与释放。
2. 原生画布的内部复制会向系统剪贴板放入说明文本。占用适配层绕过原生 paste capture、直接向输入框插入 plain text，导致内部标记被当成普通文字。现在保留所有格式及文件，先让原生捕获处理，再对未消费事件模拟默认文本插入。没有证据表明纯鼠标连线会自行触发系统粘贴。
3. 保存被明确拒绝时，新版本可能已先通过实时消息进入客户端。随后安装的 CAS 等待标记却只等待下一次新事件；服务器没有继续变化时，该标记永久保留。明确拒绝的请求现在可使用同一会话已有的新版本证明解除，未知提交结果仍需要新的完整读取。静默长流会被唤醒取证，每秒最多一次，不借旧证明覆盖未知结果。
4. 真实原生画布发现连接回调顺序问题：onConnect 被异步延后，而 onConnectEnd 先执行，原生逻辑误以为没有成功连接，走补连分支；后来的回调又报告重复连线。验收包含原生成功标记与结束回调的顺序，不只测试 addEdge。
5. 历史动作迁移节点保存了 `subType=multimodal-video`。冻结表单优先按该模式找模型，找不到原有动作迁移型号时自动换成全能参考的首个型号。模型目录中实际有动作迁移，并非模型没有接入；兼容处理应按已选模型的真实模式初始化，保持模型、参数和历史，而不是把动作模型塞进错误目录。
6. 同一原生结果在页面表示中省略了 `routerParameters`，保存确认的服务端图仍含该字段；后续本地改变模型时，合并器将省略误认为远端更改，触发 `MODEL_PARAMETERS`。完整本地状态取证确认其来自同一已确认版本，没有另一个用户的写入。修复需只补齐有同版本证据的原生省略，不能用较新的服务端参数改写历史基线。
7. 输入框失焦也会经过 window 的捕获监听。原实现把输入框失焦当成窗口失焦，焦点从提示词移向节点时会取消正常拖线。现在只在真正窗口失焦、页面隐藏或取消手势时清理。
8. 无提示词的动作模型历史参数可能保留空格，而原生命令根据模型配置省略该参数。精确的忽略提示词策略现在接受这一空值投影；非空描述、模式、型号、版本、参考和历史变化仍受检查。

## 产品行为

正常编辑、临时同步追赶不显示草稿处理入口。备份存储失败、其他页面遗留备份或确实不能自动选择的同字段冲突仍可恢复，避免隐藏实际丢失风险。仅有下载文件时可显式使用 `?draftRecovery=1` 打开恢复入口；不会自动覆盖内容。

保存继续复用已有的有限重试：1、2、5 秒，最多三次。仅已安全解除等待的明确拒绝可重试；未知结果、权限撤销、换项目等仍保留保护。

观测基线只在原生挂载或确认已应用的远端图中补齐。旧草稿仅有 `initialEtag` 不足以证明它观察过该版本，不能据此自动回填新服务器参数；复核中的“新快照先到、旧观测未应用”反例仍必须保留真实冲突。

## RunningHub 实际对照

在 https://rhtv.runninghub.ai/ 创建独立临时画布，使用原生鼠标连接文字与视频、删除连接、重新连接、刷新。节点和连线保留，没有出现这两类提示。测试画布已删除，没有触发生成或其他收费调用。

当日添加节点菜单有 12 个入口，但不能据此给出固定的“组合总数”：合法性还取决于模型、端口、数量、素材类型及状态。产品应支持合法的编辑操作，把输入限制明确呈现；不能把接口同步顺序问题交给用户处理。历史采集文档记录过 Yjs/WebSocket，本轮没有抓取其当前实时协议，不据此推断其内部实现。

## 验收方式

本地隔离 API 使用脱敏后的五节点形状、合成图片/视频和真实 CAS、占用及 SSE 协议；页面为正式构建、冻结 React/ReactFlow、WCn/Yjs 与正式保存客户端。没有简化 manager、直接 setNodes 或以模拟页面替代原生交互。模型任务端点禁用，不能把本次交互通过解释为模型生成成功。

浏览器高层自动化鼠标 API 会在步骤间短暂改变页面可见性，原生画布正确地取消后台拖拽。因此连线验收使用同一浏览器目标的 CDP 真实 Input 鼠标事件，保持页面可见；没有替换应用事件监听或关闭占用保护。

原生浏览器已确认：打开已有动作迁移结果仍保留同一模型；断开图片连线后重连，五个节点和五条连线保存成功；刷新后结果、历史和连线保留。将删除连线的 PUT 延迟两秒，在它返回前重连，最终连续两个保存均为 200，页面保留最新连接，无草稿阻塞或重复连线提示。

另以 250 ms 网络响应延迟验证完成拖拽后才取得占用，连线仍保存；两个实际原生页面最终均显示五条连线，无草稿阻塞，在线人数为一人。提示词框实际聚焦后拖动源视频连线亦通过；断开时生成按钮提示缺少动作视频，补回后自动恢复可执行。测试没有点击生成按钮调用模型。

最终前端全量回归 175 个文件、3,373 项通过，类型检查和正式构建通过。冻结资源基线 1,198 个文件不变，契约 66 项通过；指南 5 节、131 张图，新增真实原生画布重连截图。执行回归使用真实冻结 q_/MCe/W8 与实际执行适配器，验证旧动作模型命令可提交本地协议端点，伪造模式、版本、参数、描述、参考或历史无法借兼容投影通过。
