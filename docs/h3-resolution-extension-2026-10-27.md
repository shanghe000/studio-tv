# H3 480P／768P 十二种尺寸扩展

2026-10-27。新增独立分辨率扩展工作流和服务候选配置，保留原有首帧／首尾帧、文戏、武戏和SGUN长片。新规格处于 **CANDIDATE／待GPU验收**，不冒用旧规格的GPU证据，也不更改已发布v1的预设和任务身份。

## 尺寸与工作流支持

| 显示构图 | 480P | 768P |
| --- | --- | --- |
| 宽屏（名义16:9） | 864×480 | 1344×768 |
| 竖屏（名义9:16） | 480×864 | 768×1344 |
| 方形 | 480×480 | 768×768 |
| 4:3 | 640×480 | 1024×768 |
| 3:4 | 480×640 | 768×1024 |
| 超宽屏21:9 | 1120×480 | 1792×768 |

这些尺寸均为32的倍数。当前官方ComfyUI v0.42.1中，H3视频VAE使用16倍空间压缩，DiT进一步使用2×2潜变量分块，目标宽高可直接输入；它们在形状层面可配置。无需为不同比例另外下载H3、编码器、VAE或LoRA权重。参考视频预处理的`768×1344`面积限制不是目标生成节点的硬上限。目标像素数提高仍会增加计算负载，且不能仅凭节点接受参数断言画质、显存和速度已验证。

执行参数使用真实像素约分比例：864×480为9:5、480×864为5:9；1344×768为7:4、768×1344为4:7。宽屏／竖屏是展示分组，不能把名义16:9／9:16直接传给严格比例校验。超宽屏1792×768的面积比1344×768大约33%，需单独观察质量和显存。

## 接入边界

- 文戏、武戏新增独立v2候选profile；本轮候选服务统一约5秒、24fps，以减少未经验证的尺寸／时长组合。ComfyUI图中的时长控件继续保留，修改时长属于额外试验。
- 保留原有模型、LoRA、sigma与采样链，通过轻量规格选择节点向原H3条件节点输出宽高。原官流文件不覆盖；首帧／首尾帧在独立UI副本中共用相同的12规格选择节点。
- 云端白名单同时校验宽高、规格ID、时长和fps。Router公开能力版本及参数版本均为2，精确绑定云端工作流摘要和12个预设。
- 候选`available=false`，不带GPU验收证明。Router拒绝执行，画布继续沿用隐藏不可用能力的行为；前端已准备v2的比例同步和故事板保存适配。
- SGUN的20／30秒长片保留当前已验证480P配置；本轮不连带扩大其尺寸／时长组合。2K不在本轮范围内。

## 无卡启动状态与验证

本次检查时ComfyUI的6006端口未监听。其普通启动日志在CUDA初始化处因找不到NVIDIA驱动而退出；私有API的6009端口仍健康，但这不能证明推理服务就绪。实例为无GPU的维护模式，不重装PyTorch、不更换驱动、不发起付费API或生成任务。

验证包括：当前云端源码摘要比对、H3潜变量与帧数对齐的静态检查、12规格选择节点与工作流连接、API编译精确宽高、候选拒绝执行、旧v1文件保持、Router参数合同及前端序列化回归。静态验证不能代替GPU采样、VAE解码、音视频完整性和实际画质检查。

GPU恢复后的发布门槛：逐模型、逐尺寸生成约5秒样片；核对实际宽高、24fps、帧数与声音，观察显存和用时；检查文件回收、画布选择、保存与重开。只有对应规格通过后才新增正式版本和真实GPU验收记录。现有Router视频回收上限64MiB，也需纳入检查。
