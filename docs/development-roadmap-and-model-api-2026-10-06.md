## 开发和交付顺序

| 阶段 | 交付功能和完成标准 | 用户准备的模型能力 | 何时准备 |
| --- | --- | --- | --- |
| 1 已上线：画布同步与执行输入 | 选中的历史产物正确用于下游；图片、视频、音频按明确顺序传入；打开的画布同步远端修改，保留未保存内容；切换作品和退出登录停止旧订阅 | 无新增模型，使用现有能力与隔离测试服务 | 现在不用准备密钥；可先提供后续接口文档 |
| 2 已上线：普通单节点后台保存 | 页面关闭后任务仍完成并保存；旧任务不能覆盖已改动或删除重建的节点；刷新后状态和历史一致 | 现有文字、图片理解、文生图、单图编辑即可 | 文字、图片已真实验收；视频和音频待各自模型接入 |
| 3 已上线（首批范围）：Agent 文字工具闭环 | 按用户身份读取画布、创建和连接节点、发起生成、查询真实状态；结果自动显示，重新登录仍可见；验证隔离、重放和恢复后切换新请求至直接 Codex 链路 | 首批 Codex 纯文字历史与动态工具调用，以及已有图片生成和单图编辑运行时；直接多模态对话另行验收，暂不需要新供应商 | 阶段 2 时准备独立运行目录与登录配置；迁移由开发处理，不让两条链路写同一运行目录 |
| 4 分镜图到镜头视频 | 普通图生视频先完成；首尾帧作为独立能力验收；视频真实导入、播放、历史选择和下游复用 | 至少一个图片＋提示词→视频接口；如支持首尾帧须明确两种输入角色；文生视频可同批但单独声明 | 阶段 3 开发期间交付文档、测试入口和限制说明 |
| 5 图片精修和一致性 | 多参考图用于人物、场景和道具；局部重绘、扩图、透明抠图、超分逐项开放 | 多参考编辑；原图＋蒙版局部编辑；扩图；真实 Alpha 抠图；超分。可来自多个接口，无需一个模型包办 | 视频阶段结束前准备优先需要的一至两项，其余分批提供 |
| 6 声音和动作 | 配音与镜头时间线结合；按实际能力加入音乐、动作模仿和对口型 | TTS 优先；音乐；目标角色图＋动作视频；人物图或视频＋音频→对口型视频，各为独立能力 | 每个子功能开始前准备对应入口和一组合法测试素材 |
| 7 专项工作流 | 扩展导演、批量分镜、整组依赖执行、失败分支重试和完整取消恢复；3D 单独验收 | 调度本身无需新模型；3D 需真实几何或场景文件输出接口；视频理解、分层、相机或布光按具体功能补齐 | 按已选功能准备，避免一次部署所有候选模型 |

阶段 1 至 3 为共同基础，顺序固定。用户已确认新增模型优先视频首帧与首尾帧；阶段 5 至 6 可按提供的接口调整。导演和分镜中能由现有文字、看图、图片能力完成的部分可以提前，专用控制能力不能由提示词冒充。完整批量编排在单节点可靠执行基础上扩展，阶段 2 已须处理基本任务失败、恢复和结果归属。

每阶段完成后报告：可操作入口、完成的验收、仍受限的功能、是否上线，以及下一阶段需要的接口。未具备真实能力的菜单保持不可用，不自动回落 mock 或其他型号。

## 每个模型入口交付的信息

第一批供应方案已由用户确定：云端部署 MiniMax H3 量化版，先接 FL2VA，再接全能参考 Ref2VA。具体量化权重、服务框架、版本和 API 地址尚待交付。

## H3 视频接入批次

| 批次 | 无限画布中的用途 | 部署侧需要提供 |
| --- | --- | --- |
| 4A FL2VA | 分镜图动起来、首帧引导、首尾两帧间的镜头；无图片的文生视频按实际支持再开放 | 首帧、尾帧明确分开传入；生成提示词、实际时长和分辨率参数；提交任务、查询和下载结果 |
| 4B Ref2VA | 视频节点的全能参考；混合角色图、场景图、参考视频或音频生成镜头 | 有序的图片/视频/音频引用；提示词中的引用编号规则；每类素材和混合总量限制；角色或时间区间是否可显式指定 |

全能参考是已有画布功能需求，值得准备。FL2VA 和 Ref2VA 会分别注册能力和版本，不因共用 H3 名称混用输入。官方区分首尾帧与多模态参考两个变体；自部署的量化版仍须逐项实测其封装是否完整暴露这些输入。H3 Base 也不自动等于包含官方上下文预处理和 2K 再生成流程。[MiniMax 官方模型说明](https://huggingface.co/MiniMaxAI/MiniMax-H3)

目前无需为了 STUDIO 先统一成 OpenAI 协议。可提供实际 HTTP 服务协议，或明确的 ComfyUI API 工作流及输入节点映射，由 STUDIO 服务端封装。生成的视频带声音也不意味着独立配音、音乐或专用动作迁移已验收；这些仍按后续阶段分别处理。

## 通用接口交付清单

先提供以下资料即可开始适配；接口不必统一成一种协议，STUDIO 在服务端适配。

1. 服务名称、准确模型 ID 和版本、文档地址、可从 deployment-host 访问的 Base URL。
2. 明确支持的功能，例如文生图、单参考编辑、多参考编辑、首尾帧视频；不能只写“全能模型”。
3. 一份不含真实密钥的最小请求与成功响应，以及至少一份失败响应。
4. 输入方式：上传文件、Base64、可访问 URL 或素材 ID；最大文件大小、数量、格式，以及图片/视频/音频角色和顺序。
5. 输出方式：文件字节、下载 URL 或任务 ID；MIME、尺寸、时长、帧率、音轨或 Alpha 支持；下载鉴权和链接有效期。
6. 支持的参数和范围：比例、分辨率、时长、参考强度、seed 等；不支持的参数直接标明。
7. 同步或异步执行；异步提供状态查询、终态和错误码，说明取消、回调签名、幂等及超时后查询是否可用。
8. 并发与速率限制、通常耗时、计费方式；是否有免费测试环境，以及允许的真实验收调用数量或预算。
9. 鉴权方法和服务器秘密文件路径。密钥不贴聊天、不写文档或仓库、不下发浏览器。

不要求上游天然支持取消或幂等；不支持时 STUDIO 必须如实呈现限制，并避免在提交结果未知时盲目重发。上游只提供外链时还需确认 deployment-host 能下载真实结果，不能把一段文字或占位 URL 当作生成成功。

## 各类能力的额外验收条件

| 能力 | 需要额外确认 | 最小真实验收 |
| --- | --- | --- |
| 图生视频和首尾帧 | 单首帧与首尾帧是否不同模型；时长、画幅、分辨率；是否带声音 | 真实可播放视频、条件图片与角色传递正确、时长和历史记录正确 |
| 多参考图 | 最大张数、输入顺序、人物/场景等角色是否明确支持 | 三张参考的请求内容可追溯，质量满足约定；不把不同素材静默裁成一张 |
| 局部重绘和扩图 | 蒙版白/黑含义、Alpha 与坐标系、原图与蒙版尺寸、扩展边界 | 被选区域改变且非选中区域保持符合约定；边界与输出尺寸正确 |
| 抠图和图层 | 真实透明通道、图层列表、坐标与层级、背景补全能力 | 下载文件实际含 Alpha 或完整图层；纯色背景不冒充透明 |
| 超分 | 目标尺寸和倍率、输出上限、细节保持 | 实际分辨率达到要求，并评估细节和人物一致性 |
| 配音和音乐 | 语言、音色、输出格式和采样率、时长限制；配音是否提供时间戳 | 可播放音频、真实时长、剪辑同步；声音 ID 与请求一致 |
| 动作模仿和对口型 | 身份图、动作视频、音频分别如何传入；最大时长和帧率 | 独立验证身份保持、动作或嘴型匹配、声音时序 |
| 3D | 输出格式、是否带纹理、坐标/单位、外部文件依赖 | 文件可被实际解析和展示，不以图片预览代替三维产物 |

## 需要用户决定的事项

- 下一类模型优先级已确认：视频首帧与首尾帧。图片精修、声音和动作的后续顺序可按接口准备情况调整。
- 新服务实际开放的能力、模型版本和入口：依据接口资料决定，开发不猜测。
- 新付费服务的真实验收调用范围：先完成可复核的适配和测试，再按用户提供的次数或预算进行真实调用。

常规实现、隔离测试和既定范围内的修复继续推进，不逐项重复确认。历史选择失效时停止并提示重新选择，避免偷偷改用最新产物；这作为当前实现规则，不把原站的回退逻辑当作生成授权。
