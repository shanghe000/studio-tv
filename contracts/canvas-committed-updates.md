# Committed canvas updates

The database owns the canvas. A local gesture changes another page only when a graph operation has committed. The old live-snapshot, JSON replay, SSE frames and writer receipts remain valid. Authenticated clients can negotiate smaller payloads. All graph fragments use the canonical v1 encoded graph, including the native metadata node.

| Transport | Negotiation | Result |
| --- | --- | --- |
| First read | GET `/api/v2/projects/{projectId}/live-snapshot` without query parameters | Original full shape. Header `X-STUDIO-Canvas-Update: delta-v1` advertises the optimization. |
| Catch-up read | GET `/api/v2/projects/{projectId}/live-update?fromRevision=N` | `kind: DELTA` with exact `fromRevision` and `delta`, or `kind: SNAPSHOT` with the original `graph`. Both include `schemaVersion`, `projectId`, `graphRevision`, `eventCursor`, `updatedAt`, complete `nodeStates`, and `nodeExecutionAvailable` from the same authorized repeatable-read transaction. |
| SSE | GET the existing SSE event stream with `X-STUDIO-Canvas-Update: delta-v1` | For a single current-head invalidation, replace its frame with the original `id`, event type `canvas.delta`, and the catch-up DELTA DTO as data. The durable event remains unmodified. |
| Write acknowledgment | POST the existing operation batch with `X-STUDIO-Canvas-Receipt: delta-v1` and `X-STUDIO-Canvas-Base: N` | A supported change returns the original `revision`, `eventCursor`, `updatedAt`, `clientId`, `batchId`, `acceptedRevision`, `acceptedAt`, optional `supersededOperations`, and `kind: DELTA`, `fromRevision`, `delta`. Otherwise the original full receipt is returned without a new kind. A matching unchanged revision can have an empty delta. |
| Uncertain acknowledgment | Retry the identical batch ID and body with `receiptOnly:true`, omitting negotiation headers | Full receipt/current canonical snapshot if previously committed; otherwise the existing definite-not-applied response. Never performs a new edit. |

`N` is the client's confirmed canonical revision in positive canonical decimal form, at most 2^53−1. It is separate from the persisted batch's `observedRevision` (the native view that originated its edits) and the strict recovery `baseRevision`. Negotiation headers do not change the idempotency digest. Missing or invalid writer headers fall back to the original receipt. The new read route rejects unknown query fields, duplicate parameters, zero, signs and leading zeroes.

The delta has five always-present arrays: `positions` entries are `{id,x,y}`, `upsertNodes` and `upsertEdges` contain complete canonical rows, and `removeNodeIds` and `removeEdgeIds` contain the removed IDs. Optional `nodeOrder` and `edgeOrder` contain the entire resulting entity order when it changed. Apply the delta only to the exact matching canonical base and verify row identities, endpoints and order before exposing the result. Keep view-local selection, viewport, drafts and pending operation intents separate. If application or acknowledgment is uncertain, request a full read or the full receipt. Never advance the event cursor before the graph and execution state have actually been installed.

Only validated operations create index entries after successful commit. Each entry records changed object IDs, flags, before/after SHA-256 digests and a short expiration. The process stores no historical graph JSON or prompt bodies in that index. A bounded pre-commit notification contains only a project ID and revision; it lets a reader wait up to 30 ms for Go to publish a proven commit after PostgreSQL has already woken the reader. A notification without a matching committed digest cannot return a delta. Every read still verifies live project access and reads the current authoritative graph. SSE revalidates the login and authorization proof after preparing the frame.

A read folds at most 24 adjacent indexed revisions over at most 64 changed objects. Position-only updates may refer to any intact node incarnation. Other upserts/removals are restricted to small supported node types with no execution state (8 KiB per row). Changes to the outer graph or viewport, task/worker and unindexed writes, missing or mixed revisions, different processes, restart, eviction and excessive complexity fall back to a full snapshot. The encoded graph delta is capped at 64 KiB. Execution state metadata is additional. Indexes have a five-minute lifetime, at most 1,024 records and a 4 MiB size budget.

An isolated PostgreSQL acceptance fixture with 242 synthetic nodes changed one node position. Actual uncompressed HTTP response bodies were 483 bytes for the negotiated writer receipt versus 388,361 bytes for its full receipt; the observer read was 384 bytes versus 388,262 bytes for the full snapshot. A negotiated SSE connection received the same change in a 369-byte data frame without making the catch-up request. These sizes depend on the graph and metadata.
